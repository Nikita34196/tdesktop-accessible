# Как внести вклад

Спасибо за интерес к проекту! Вот как можно помочь:

## Тестирование

Самое ценное — тестирование с реальным скринридером.

1. Скачайте сборку из [Releases](../../releases)
2. Запустите с NVDA / JAWS / Narrator
3. Проверьте: какие элементы озвучиваются? какие нет?
4. Создайте Issue с описанием: что не работает, что ожидалось

## Разработка

1. Форкните репозиторий
2. Внесите изменения в файлы `accessibility/`
3. Создайте Pull Request с описанием

### Что можно улучшить

- Озвучивание уведомлений о новых сообщениях
- Голосовые сообщения: пауза и перемотка с клавиатуры
- Чтение реакций и цепочек ответов
- Навигация по результатам поиска стрелками с озвучкой

## Сотрудничество с официальным Telegram Desktop

С 2025 года в [telegramdesktop/tdesktop](https://github.com/telegramdesktop/tdesktop) появилась встроенная поддержка скринридеров (PR [#29808](https://github.com/telegramdesktop/tdesktop/pull/29808), обсуждение в [#476](https://github.com/telegramdesktop/tdesktop/issues/476)). Наш форк по-прежнему полезен как «полный» слой для NVDA, но часть наработок имеет смысл переносить upstream.

### Что у официального клиента стоит заимствовать

| Тема | Зачем нам |
|------|-----------|
| Режим **Screen Reader** (авто + отключение в настройках) | Меньше ломать обычных пользователей, единая семантика с tdesktop |
| **Прочитано по фокусу**, а не по видимости ([#31032](https://github.com/telegramdesktop/tdesktop/pull/31032)) | Счётчик непрочитанных совпадает с тем, что реально озвучил NVDA |
| Фокус **списка чатов при старте** в SR-режиме | Нет «пустого» Qt-контейнера при запуске |
| Детальная разметка **HistoryView** (`MessageSubItem`, sub-elements) | Более точная озвучка частей сообщения без костылей |
| Открытые PR: заголовки поиска ([#30722](https://github.com/telegramdesktop/tdesktop/pull/30722)), **PeerList** ([#30755](https://github.com/telegramdesktop/tdesktop/pull/30755)) | Следить и портировать после мержа |

База tdesktop **зафиксирована** тегом `TDESKTOP_REF` в CI (см. [docs/UPSTREAM_BUMP.md](docs/UPSTREAM_BUMP.md)). Поднятие версии — по чеклисту там; скрипт `scripts/a11y_upstream_patches.py` — для точечных правок поверх выбранного тега.

### Что у нас сильнее — кандидаты на upstream

- **F6 / Ctrl+Tab** — цикл по панелям с понятными именами.
- **Ctrl+Shift+F / U / P / I** и клавиатура в **списках медиа** (Enter, Tab, контекстное меню).
- **Tab по ссылкам и кликабельным зонам** в сообщении с защитой от крашей на plain text.
- Интеграция **NVDA** (`SpeakForced`, тест **Ctrl+Shift+T**) — лучше выносить как опциональный модуль или документировать паттерн, а не жёстко в ядро.
- Озвучка **«печатает…»**, бот-клавиатура, расширенные патчи из `a11y_upstream_patches.py`.

### Как предложить изменения в tdesktop

1. Подписать [CLA](https://cla-assistant.io/telegramdesktop/tdesktop) (обязательно для PR).
2. Один PR — одна тема: только Qt/`QAccessible`, без `nvdaControllerClient`, если возможно.
3. В описании PR: сценарий NVDA/JAWS, шаги, ссылка на наш Issue/релиз.
4. В [#476](https://github.com/telegramdesktop/tdesktop/issues/476) кратко описать форк и спросить, какие куски интересны мейнтейнерам; можно сослаться на автора [#29808](https://github.com/telegramdesktop/tdesktop/pull/29808) для выравнивания API.
5. Готовить патчи как минимальный diff к актуальному `tdesktop` (не весь overlay) — у нас ориентир: `accessibility/` + отдельные `scripts/patch_*.py`.

## Отчёты об ошибках

Создайте Issue и укажите:
- Версию Telegram Accessible
- Версию NVDA / JAWS
- Версию Windows
- Шаги для воспроизведения
- Что произошло vs что ожидалось
